# Plan 13-01: Order Management System (OMS)

## Objective
Build the OMS to manage the full order lifecycle with state machine tracking, idempotent submission, limit-order-first execution, candle-based expiry, and SQLite-backed persistence.

## Tasks

- [ ] **1. Order Data Models**
  - Create `src/algoforge/oms/models.py`.
  - Define `OrderStatus` enum (NEW, SUBMITTED, PARTIAL_FILL, FILLED, CANCELLED, REJECTED).
  - Define `OrderType` enum (LIMIT, MARKET).
  - Define `Order` pydantic model with correlation_id, symbol, direction, order_type, price, quantity, status, max_candles, elapsed_candles.

- [ ] **2. State Machine**
  - Create `src/algoforge/oms/state_machine.py`.
  - Implement `transition(order, new_status)` with strict valid-transition enforcement.
  - Terminal states: FILLED, CANCELLED, REJECTED.

- [ ] **3. SQLite Persistence**
  - Create `src/algoforge/oms/store.py`.
  - Implement `OrderStore` with `save_order`, `update_order`, `get_active_orders`, `get_order_by_correlation_id`.
  - Auto-create table on init.

- [ ] **4. OMS Manager**
  - Create `src/algoforge/oms/manager.py`.
  - Implement `OrderManager.submit_order(order)` with idempotency check.
  - Implement `OrderManager.check_expiry()` to cancel stale limit orders.
  - Implement `OrderManager.fill_order(correlation_id)` and `OrderManager.cancel_order(correlation_id)`.

- [ ] **5. Integration & API**
  - Create `src/algoforge/oms/__init__.py`.
  - Export public classes.

- [ ] **6. Testing & Verification**
  - Create `tests/unit/test_oms.py`.
  - Test state machine transitions (valid and invalid).
  - Test idempotency (duplicate correlation IDs rejected).
  - Test candle expiry cancellation.
  - Test SQLite persistence round-trip.
